# vak-repositories-pg: Postgres implementations

## Responsibility

This crate implements the `vak-repositories` ports on Postgres 18 with sqlx 0.9. It owns:

- `migrations/`: forward-only `<timestamp>_<name>.sql` files, embedded with `sqlx::migrate!()` and run by `vak-server migrate`
- `.sqlx/`: the committed offline query cache, generated by `just db-prepare` and **never hand-edited**
- connection pool setup (`Database`, `DatabaseConfig`) and, later, Lakebase credential refresh through `vak-databricks-auth`
- the `JobQueue` implementation (apalis-postgres, later)

Today:

| Item | What |
|---|---|
| `Database::connect_lazy(&DatabaseConfig)` | Pool that connects on first use; statement timeout, acquire timeout and pool size from the config. The URL is a `SecretString` and never appears in errors |
| `Database::migrate()` | Applies pending migrations |
| `PgAgentRepo` | `AgentRepo`: each mutation is one transaction (operator upsert, agent, draft, audit event) |

| Migration | Tables |
|---|---|
| `20261030120000_workspaces_operators` | `workspaces` (one seeded default, `01923a00-0000-7000-8000-000000000001`), `operators` (from the forwarded identity) |
| `20261030120100_agents` | `agents` (name, use case, jurisdiction, revision, archived_at), `agent_drafts` (persona and settings JSONB, rule pack, content hash) |
| `20261030120200_audit_events` | `audit_events`, append-only: triggers reject UPDATE, DELETE and TRUNCATE (SQLSTATE 42501) |

## Dependencies

- **May depend on:** `vak-repositories`, `vak-domain`, `vak-databricks-auth`. Dev-only: `vak-testkit`.
- **External crates:** `sqlx` (this is the only crate allowed; `deny.toml` `wrappers`), `jiff-sqlx` (timestamps; also a sqlx wrapper), `serde` (JSONB shapes), `uuid`, `thiserror`, `secrecy`; later `apalis-postgres`.
- **Must not depend on:** services, api, providers, pipeline, adapters, axum, reqwest.

## Conventions

- **SQL:** raw SQL with compile-time checked macros (`query!`, `query_as!`). Timestamps bind as `jiff_sqlx::Timestamp`.
- **Dynamic SQL:** it needs `AssertSqlSafe` and a comment explaining why. Never use `format!`.
- **Port boundary:** map every sqlx error into `RepoError` (unique violation → `Conflict`, row not found → `NotFound`, anything else → `Unavailable`). sqlx types never cross the port.
- **Rows go through the domain:** every value read back is parsed by its domain type, and the stored content hash is recomputed and compared. A row the domain rejects is `Unavailable`, never an `Agent`. CHECK constraints repeat the domain's rules.
- **IDs and snapshots:** UUIDv7 IDs come from the domain, with `uuidv7()` as the column default. Published versions (M6) are immutable JSONB snapshots.
- **Workspace:** the MVP has one workspace; the repository scopes every query to the seeded default.
- **Postgres features:**
  - job claims: `FOR UPDATE SKIP LOCKED`
  - per-campaign limits: advisory locks
  - wake-ups: `LISTEN/NOTIFY`
- **Timeouts:** every query runs under the statement timeout and pool acquire timeout from `DatabaseConfig` (5 s each by default). No unbounded waits.
- **Credentials:** they are `SecretString`. The Lakebase OAuth token is the password and is refreshed hourly (M7). Never log connection strings.
- **Offline builds:** `backend/.cargo/config.toml` sets `SQLX_OFFLINE=true`. After changing a query or migration, run `just db-prepare` and commit `.sqlx/`. A missing cache entry fails the build.

## Testing

- `#[sqlx::test]` gives each test a fresh database with migrations applied. Postgres comes from the nextest setup script `backend/tools/test-db.sh`: one Docker container per worktree, started on demand, locally and in CI alike.
- `tests/agent_repo.rs` runs the `vak-testkit` conformance suite (the same suite the in-memory fake passes), plus the append-only audit trigger, operator upserts, rows the domain rejects, migrations on an empty database, and URL redaction.

## Coverage floor

**85%** line coverage (`coverage.toml`).

## Example

```rust
#[sqlx::test]
async fn pg_agent_repo_conforms(pool: PgPool) {
    let repo = PgAgentRepo::new(pool.clone());
    agent_repo_conformance(&repo, |id| audit_trail(&pool, id)).await;
}
```
